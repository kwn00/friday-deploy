# v0.3.2

## 달라진 점

- **메뉴에서 가진 아이템 보기.** 게임 중에 메뉴(Ⅱ 버튼, Esc, P)를 열면 가진 무기와 패시브가 무기 묶음(`무기 3/6`)과 패시브 묶음으로 나옵니다. 혼자 하기와 함께 하기 모두, 연결이 끊겨 저절로 뜬 메뉴에서도 보입니다. 아이템마다 다음이 나옵니다.
  - 단계: `Lv.3/8`. 최대 단계는 '최대' 표시, 진화한 무기는 ★.
  - 한 줄 설명.
  - **지금 효과**:
    - 패시브는 그 패시브의 지금 단계까지 합친 효과입니다 (아이스 아메리카노 3 → 이동 속도 +30%, 기계식 키보드 2 → 쿨다운 -16%). npm install·다크 모드처럼 단계마다 곱해지는 것은 곱으로 보여 줍니다 (npm install 3 → 끌어당기는 범위 ×2.49).
    - 무기는 가진 패시브까지 넣은 지금 수치입니다: 피해, 개수, 쿨다운, 지속, 관통(끝없이 꿰뚫으면 '무한'), 확률, 치명타. 범위·속도는 그 무기 1단계 대비 % 로 씁니다. 무기가 받지 않는 패시브의 능력치나 그 무기에 뜻이 없는 값은 뺍니다.
  - 다음 단계에서 좋아지는 것 (레벨업 카드와 같은 문구).
  - 진화 안내: 진화의 짝, 보물상자를 열면 진화할 무기(노란 테두리, '🎁 지금 보물상자를 열면 진화해요'), 진화한 무기의 재료(보라 테두리).
  - 맨 아래에 되살아날 수 있는 횟수 (백업과 스냅샷을 합친 수).
- **러버덕**은 쿨다운 대신 실제로 도는 시간과 쉬는 시간을 보여 줍니다. 오리는 (쿨다운 + 지속) × 쿨다운 배율마다 다시 나오고 지속 × 지속 배율 동안 돌아서, 쿨다운 숫자로는 언제 도는지 알 수 없었습니다. keep-alive 로 도는 시간이 주기보다 길어지면 '쉬는 시간 없음 (계속 돌아요)' 입니다.
- **스프린트**는 쉬지 않고 걸으면 더해지는 피해의 상한('걸으면 피해 최대 +40', 단계 × 5)을 함께 보여 줍니다.
- 메뉴가 열려 있는 동안 강화가 바뀌면 (함께 하기에서 레벨업 선택·보물상자) 목록도 바로 바뀝니다.
- 화면: '계속하기'는 어느 화면 크기에서든 스크롤 없이 보이고, 목록만 메뉴 안에서 따로 스크롤됩니다. 세로 폰은 계속하기 → 목록 → 미니맵·효과음·음악 → 그만두기 순서이고, 넓은 화면과 가로 폰은 왼쪽에 버튼, 오른쪽에 목록입니다. 키보드로는 Tab 으로 목록을 고른 뒤 방향키·PageDown·End 로 스크롤합니다.

## 내부 변경

- `apps/client/src/loadout.ts` (새 파일): 내 강화 단계와 부활 수 → 묶음별 줄 데이터. 수치는 서버 시뮬레이션과 같은 공용 함수(`effectiveStats`, `moveSpeedOf`, `cooldownMultOf` 등 `packages/shared/src/stats.ts`)로 계산하고, 화면은 서버가 스냅샷에 실어 보낸 내 강화 단계로 보여 주기만 합니다. 통신 규격과 서버 판정은 바뀌지 않았습니다.
- 러버덕의 주기는 `combat.ts` 의 `runDucks` 와 같은 식(`duckCycleOf`)으로 조합합니다. 식이 두 곳에 있으므로, 실제 시뮬레이션을 돌려 잰 주기·도는 시간·쉬는 시간과 화면 값을 비교하는 테스트로 묶었습니다 (`runDucks` 를 바꾸면 이 테스트가 실패합니다).
- 스프린트: 걸으면 더해지는 피해의 상한을 공용 상수 `SPRINT_BONUS_PER_LEVEL` (5) 로 뺐습니다 (동작은 같습니다). 스프린트의 지속은 베는 모습을 얼마나 보여 줄지에만 쓰이므로, 다른 베기·번개 무기처럼 `ignores` 에 `dur` 을 넣었습니다: keep-alive 가 있어도 베는 모습이 길어지지 않습니다. 피해와 판정은 그대로입니다.
- 화면 (`index.html`, `main.ts`, `style.css`): 메뉴를 머리(제목·설명·방 코드)와 몸(계속하기, 목록, 버튼)으로 나눴습니다. 목록은 `node()` 와 `textContent` 로만 그립니다. 메뉴를 열 때와, 열려 있는 동안 강화가 바뀔 때만 다시 그립니다. 새 판이 시작되면 지난 판의 강화 단계를 비워서, 첫 스냅샷 전에 메뉴를 열어도 지난 판의 목록이 보이지 않습니다.
- 서버 CPU 와 전송량은 그대로입니다. 처음 화면을 받을 때 gzip 기준 약 4kB 가 늘었습니다 (JS 43.07 → 46.07kB, CSS 4.45 → 5.21kB, HTML 2.97 → 3.25kB).
- 테스트: `loadout.test.ts` (새 파일, 9개), `layout.test.ts` 에 메뉴 배치 1개.
- 리더보드 시즌, 기록 형식, 통신 규격 버전은 그대로입니다. 지운 기록은 없습니다.

## 확인한 것

- 단위 테스트 313개 통과 (PostgreSQL 저장소 테스트 31개 포함).
  - 무기 수치: 모든 무기 × 모든 단계 × 패시브 조합 5가지(패시브 15종을 모두 최대로 둔 경우 포함)에서 모든 줄이 `effectiveStats` 와 같습니다.
  - 패시브: 15종 × 모든 단계의 효과가 `stats.ts` 함수 값과 같습니다.
  - 러버덕: 실제 시뮬레이션을 단계 8개 × 패시브 조합 8가지로 80초씩 돌려 잰 값과 같습니다 (한 틱 0.05초 안).
  - 계산을 일부러 틀리게 바꾸면 테스트가 실패하는 것도 확인했습니다.
- 실제 서버와 브라우저(Chromium)로 확인했습니다.
  - 혼자 하기: 레벨업으로 실제로 얻은 무기·패시브가 메뉴에 나오고, 메뉴 동안 시간이 멈추고 계속하기로 이어집니다.
  - 함께 하기: 메뉴를 연 동안에도 시간이 가고, 서버가 대신 고른 레벨업으로 목록이 바로 바뀝니다.
  - 연결이 끊겨 저절로 뜬 메뉴에도 목록이 나옵니다.
- 무기 6개·패시브 6개를 가진 상태(진화 준비, 진화한 무기, 최대 단계, 러버덕·스프린트 포함)를 320×568 · 390×844 · 568×320 · 844×390 · 1280×800 에서 확인했습니다. 이 상태는 화면이 받은 강화 단계를 테스트 스크립트에서 바꿔 넣어 만들었습니다.

  - 가로 스크롤이 없고, 버튼은 모두 44px 이상입니다.
  - 목록만 스크롤되고, 손가락으로 끌기와 키보드(Tab → 방향키·End)로도 스크롤됩니다.
