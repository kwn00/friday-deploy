# v0.1.1

## 달라진 점

- **캐릭터가 누르는 즉시 움직입니다.** 전에는 키를 누르거나 화면을 끌어도 입력이 서버를 다녀온 뒤에야 캐릭터가 움직여서 한 박자 늦었습니다. 이제 내 캐릭터는 입력대로 바로 움직이고, 손을 떼면 그 자리에 바로 섭니다.
  - 왕복 지연 120~180ms 를 넣은 환경의 실제 브라우저에서 쟀을 때, 키를 누른 뒤 화면이 움직이기 시작할 때까지 약 233ms → 약 34ms (0.1.0 과 비교, 중앙값).
- 걷는 그림과 바라보는 쪽도 입력을 바로 따라갑니다.
- 다른 것들(버그, 동료, 경험치, 공격)은 전과 같이 서버가 보낸 대로 그립니다. 그래서 움직이는 동안에는 내 캐릭터가 주변보다 조금 앞서 보입니다. 맞았는지, 주웠는지는 전과 같이 서버가 서버 위치로 판정합니다.

## 내부 변경

- **클라이언트 예측** (`apps/client/src/predict.ts`): 내 캐릭터(와 카메라)를 서버의 가장 최근 위치에 "보냈지만 서버가 아직 반영하지 않은 입력"만큼을 더한 자리에 그립니다. 예측이 서버와 어긋나면 약 0.1초에 걸쳐 맞추고, 40px 넘게 어긋나면 바로 옮깁니다. 서버의 답이 오지 않아도 0.4초 거리보다 더 앞서 나가지 않습니다. 월드가 멈춰 있는 동안과 쓰러진 뒤(관전)에는 예측하지 않습니다.
- **서버 권위는 그대로입니다.** 클라이언트가 보내는 것은 전과 같이 입력(방향)뿐이고, 예측한 위치는 서버로 보내지 않습니다. 예측을 조작해도 자기 화면만 달라집니다 (`docs/SECURITY.md` 에 반영).
- **스냅샷에 값 세 개 추가**: 서버가 마지막으로 받은 내 입력 번호, 그 입력으로 움직인 틱 수, 그 입력이 틱 사이의 어디쯤에서 도착했는지. 스냅샷 하나에 4~5바이트(평균 876바이트의 약 0.5%)가 늘었습니다. 통신 규격 버전 7 → 8.
- **서버가 입력을 도착한 때부터 적용합니다** (`sim.ts` `setInput`). 전에는 틱 중간에 온 입력을 그 틱 전체에 적용해서, 누르고 있던 시간과 실제로 움직인 거리가 최대 한 틱(3.5px)만큼 달랐습니다. 화면이 앞서 그린 자리와 서버 위치가 멈출 때마다 어긋나는 원인이라 고쳤습니다. 도착한 때는 서버 시계로 재고, 한 틱에 갈 수 있는 거리는 늘지 않습니다. 난이도에 영향이 없어 리더보드 시즌은 그대로입니다.

## 확인한 것

- 단위 테스트 136개 통과 (새로 추가: 예측 8개, 서버 3개).
  - 실제 시뮬레이션과 예측을 지연이 있는 통신(왕복 60~300ms, 스냅샷이 최대 80ms 들쭉날쭉)으로 이어 돌려서: 누른 다음 프레임에 움직이는지, 한 방향으로 갈 때 프레임마다 고르게 움직이는지, 손을 뗀 자리와 서버가 정한 자리의 차이가 0.3px 안쪽인지, 방향을 자주 바꿔도 튀지 않는지.
  - 한 틱에 기본 속도보다 멀리 갈 수 없는지 (틱 안에서 입력을 여러 번 바꾸는 경우 포함).
- 실제 브라우저(Chromium)에서 서버를 띄우고 혼자 하기: 편도 60~90ms 지연을 넣고 0.1.0 과 나란히 반응 시간을 쟀고, 320×568 · 568×320 · 1280×800 에서 움직이기 · 일시정지 · 다시 시작을 확인했습니다.
