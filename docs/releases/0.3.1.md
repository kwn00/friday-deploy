# v0.3.1

## 달라진 점

- **30분 뒤 월요일 아침은 얼지 않습니다.** 30분이 지나면 판 길이에 끝이 없고 순위는 버틴 시간이 먼저라, 코드 프리즈로 월요일 아침을 얼려 몇 분씩 더 버틸 수 있었습니다. 이제 월요일 아침은 얼지 않고(빙결 저항 1.1), 넉백에 늦춰지지도 않습니다. 디버거에 멈추지 않고 git clean 에 지워지지 않는 것은 예전과 같습니다.
- **8분 보스의 보물상자는 언제나 3개 이상.** 상자는 이제 보스마다 정해진 기본 개수보다 적게 나오지 않습니다. 예전에는 8분 왕버그 상자가 40% 넘게 1개였고, 배포 기도로 운을 올릴수록 오히려 줄었습니다 (평균 2.18개 → 이제 3.06개). 다른 보스의 상자는 그대로입니다.
- **쿨다운이 적힌 값대로.** 쿨다운이 0.05초 단위로 올림되어 실제 간격이 조금씩 길었습니다. 그래서 쿨다운 0.5초 무기(카나리아·부엉이·24시간 모니터링)에는 기계식 키보드 1단계가 아무 효과가 없었습니다. 이제 평균 간격이 적힌 값과 같습니다.
  - 기계식 키보드가 있으면 대부분 무기가 0~5% 더 자주 나갑니다. 24시간 모니터링은 최대 8.7%, 8단계 카나리아·부엉이는 키보드 1~3단계에서 10~13% 더 자주 나갑니다.
  - 키보드가 없어도 바뀌는 것: 커밋 히스토리는 0.35초가 아니라 0.3초마다 남깁니다(피해 약 17% 증가). 키보드 고양이는 0.6초마다 방향을 바꾸고, 러버덕은 6초마다 켜집니다.
  - 방화벽이 같은 적을 다시 태우는 간격도 같은 규칙입니다.
- **일시정지 예산.** 혼자 할 때 한 번 멈출 때마다 예산(한 판 30분)에서 적어도 3초를 씁니다. 짧게 껐다 켜기를 되풀이해 게임을 느리게 만드는 것을 막기 위해서입니다. 3초보다 길게 멈추면 예전과 같습니다. 남은 시간이 1분 미만이면 메뉴에 초로 보여 줍니다.
- **크리스마스 화면은 12월 26일 0시(한국 시각)까지.** 그 뒤에 화면을 새로 열면 기본 화면으로 돌아갑니다.

## 고친 것

- 초대 링크로 연 화면에서 다른 판을 하다가 새로고침하면 하던 판을 잃었습니다. 이제 초대 코드를 읽은 뒤 주소에서 지워서, 새로고침하면 하던 판이 이어집니다. 참가하기 전에 새로고침해도 방 코드는 남습니다.
- 가로로 든 휴대폰의 처음 화면에서 '참가' 버튼과 방 코드 칸의 모서리를 누르면 구석의 버전 표기나 소리 버튼이 대신 눌렸습니다.
- 가로 568×320 화면에서 순위에 오른 결과 화면의 '처음으로' 버튼이 화면 밖에 있었습니다. 이제 버튼 3개가 한 줄에 놓입니다.
- 초대 공유 창을 닫기만 해도 '링크를 복사하지 못했어요'가 떴습니다. 이제 닫으면 아무 안내도 없고, 공유가 안 되는 환경에서는 링크를 대신 복사합니다.
- 방향키로 순위표·새 소식 목록과 낮은 화면의 처음 화면을 스크롤할 수 없었습니다. 이제 방향키는 판이 진행 중이고 메뉴·선택창이 없을 때만 이동으로 씁니다.
- 보이지 않는 글자(한글 채움 문자 등)만으로 된 닉네임이 순위표에 빈칸으로 올랐습니다. 이제 이런 글자는 빼고, 남는 글자가 없으면 `anonymous` 입니다. 이미 저장된 기록은 그대로입니다.

## 내부 변경

- **서버가 통째로 죽던 것**: 화면 파일을 받다가 끊으면 읽던 파일이 닫히지 않아 열린 파일(fd)이 쌓였고, 한도에 닿으면 파일을 열지 못한 오류 하나가 프로세스를 죽였습니다 (모든 방이 끝남). 이제 파일을 연 뒤에 응답을 보내고 `pipeline` 으로 양쪽을 함께 닫으며, 열지 못하면 404/500 으로 답합니다 (`apps/server/src/static.ts`).
- **배포 때 남은 기록 저장**: Render 의 시작 명령을 `npm start` 에서 `cd apps/server && NODE_ENV=production exec node --import tsx src/index.ts` 로 바꿨습니다. `npm start` 는 npm 과 sh 가 서버를 감싸서, 종료 신호가 바깥 npm 에만 가면 서버가 아직 저장하지 못한 기록·통계를 마저 쓰지 못하고 꺼질 수 있었습니다. 종료 처리의 시작과 끝에 로그(`[server] SIGTERM: …`, `[server] 종료 (Nms)`)를 남깁니다. 감싸는 프로세스가 없어져 메모리도 줄었습니다 (로컬 측정 합계 약 230MB → 100MB).
- **배포를 일으키지 않는 파일**: `render.yaml` 의 `buildFilter` 에 `.github/**`, `.claude/**`, `.env.example`, `vercel.json`, `.gitignore` 를 더했습니다.
- **일시정지**: `PAUSE_MIN_CHARGE_MS` (3초). 기록의 `pausedSeconds` 는 예산에서 뺀 값이 아니라 실제로 멈춘 시간입니다.
- **닉네임**: `sanitizeName` 이 `\p{Default_Ignorable_Code_Point}` 를 거릅니다. 저장할 때만 거르고, 저장된 기록을 불러올 때는 다시 거르지 않습니다.
- **월요일 아침**: `monday` 의 빙결 저항 1 → 1.1. 넉백 배율이 음수인 적(월요일 아침뿐)은 끌려오는 걸음이 걷는 걸음보다 느려지지 않습니다.
- **보물상자**: `openChest` 가 `max(기본 단계, 굴린 단계)` 를 씁니다. 굴리는 순서와 비밀 난수를 쓰는 횟수는 예전과 같습니다.
- **쿨다운**: 이번 틱에 끝난 타이머는 넘친 몫(한 틱 이내)을 다음 타이머로 넘깁니다. 쏠 적이 없어 기다리던 무기는 넘기지 않아서 몰아 쏘지 않습니다. 틱당 서버 계산 시간은 그대로입니다.
- **테마**: 개발자 토글이던 `ACTIVE_THEME` 대신 날짜 표 `THEME_SCHEDULE` 와 `themeAt()` 으로 고릅니다. 보이는 것만 바꾸므로 브라우저 시계를 씁니다.
- **문서**: README, docs/SECURITY.md (새 줄: 30분 뒤 끝없이 버티기, 정적 파일 다운로드를 끊어 fd 바닥내기), CLAUDE.md. Node 하한을 20.6 으로 (`node --import`).
- 이 변경의 코드는 PR #18 로 11월 24일에 먼저 배포되었고(버전 표기 0.3.0), 이 릴리즈에서 버전과 새 소식을 더했습니다. 그 사이에 끝난 판은 통계에서 0.3.0 으로 셉니다. 이 버전부터의 판은 0.3.1 로 따로 쌓입니다.
- 리더보드 시즌, 기록 형식, 통신 규격 버전은 그대로입니다. 지운 기록은 없습니다.

## 확인한 것

- 단위 테스트 303개 통과 (PostgreSQL 저장소 테스트 31개와 DB 를 껐다 켜는 테스트 포함). 새로 추가한 테스트는 고치기 전 코드로 되돌리면 실패하는 것을 확인했습니다.
- 실제 서버를 새 시작 명령 그대로 띄웠습니다: 프로세스는 node 하나이고, 봇이 혼자 한 판을 끝까지 해 순위표·통계·DB 에 남았습니다. DB 가 꺼진 동안 끝난 판은, DB 를 켠 뒤 서버에 종료 신호를 보내자 2초 안에 저장하고 꺼졌습니다.
- 열린 파일 한도를 120 으로 낮춘 서버에서 화면 파일 다운로드를 300번 끊었습니다: 예전 코드는 약 100번에 죽었고, 고친 코드는 열린 파일 수가 그대로였습니다.
- 봇이 50ms 마다 일시정지를 껐다 켰습니다: 예전 코드는 내내 절반 속도였고, 고친 코드는 약 60초 뒤부터 거절된 뒤 제 속도였습니다.
- 30분 뒤 월요일 아침: 코드 프리즈 7단계 등을 가진 장비로 예전에는 1~6분을 더 버텼고, 이제 4초입니다 (부활 2번이면 11초).
- 8분 상자는 시드 3개 × 3000번 열어 확인했고, 다른 보스 상자의 분포는 그대로입니다.
- 실제 브라우저(Chromium)로 320×568 · 568×320 · 390×844 · 844×390 · 1280×800 등에서 고치기 전·후를 비교했습니다: 새로 생긴 가로 스크롤·잘림·작은 터치 영역이 없고, 초대 링크 새로고침, 방향키 스크롤, 구석 버튼, 공유 창, 결과 화면 버튼, 12월 27일로 맞춘 기본 화면이 고친 대로 동작합니다.
- 운영 서버에 배포된 뒤 순위표 기록(혼자 27개, 함께 3개)과 통계 API 가 그대로인 것을 확인했습니다.
