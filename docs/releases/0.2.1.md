# v0.2.1

## 고친 것

- **다른 앱이나 탭에 다녀오면 소리가 나지 않던 것을 고쳤습니다.** 돌아와서 화면을 한 번 누르면(계속하기 등) 다시 소리가 납니다. 배경음악은 곡의 처음부터 다시 나옵니다.

## 내부 변경

- **원인**: 화면을 떠나면 오디오(AudioContext)를 멈추고, 돌아오면 다시 켜도록(`resume()`) 해 두었습니다. 그런데 아이폰 Safari 는 화면을 떠났다 돌아오면 오디오가 표준에 없는 `interrupted` 상태로 멈춰 `resume()` 으로 되살아나지 않거나, `running` 이라고 알려 주면서 소리가 나지 않는 경우가 있습니다 (WebKit 에 여러 번 보고된 문제). 이전 코드는 다시 켜기만 시도해서 이 상태를 빠져나오지 못했습니다.
- **고친 방법** (`apps/client/src/audio.ts`)
  - 돌아왔을 때 오디오가 멈춰 있으면 한 번 멈췄다 다시 켜 봅니다 (알려진 우회법).
  - 화면을 떠났다 돌아온 뒤 처음 누를 때는 오디오를 새로 만들고 지난 것은 닫습니다. 되살아났는지 페이지에서 알 수 없는 경우가 있어서, 누르는 순간 새로 만드는 것이 확실합니다. 효과음·음악을 켜고 끈 설정은 그대로 따릅니다.
- 서버, 통신 규격, 게임 규칙, 리더보드는 바뀌지 않았습니다.

## 확인한 것

- 단위 테스트 통과.
- 실제 서버와 실제 브라우저(Chromium)에서, 화면을 떠났다 돌아오면 오디오가 `interrupted` 로 멈추고 다시 켜지지 않는 아이폰 Safari 의 동작을 흉내 내어 확인했습니다: 고치기 전에는 돌아와서 계속하기를 눌러도 소리가 하나도 나지 않았고, 고친 뒤에는 새 오디오로 소리가 납니다.
- 다시 켜기가 되는 브라우저(데스크톱 Chromium)에서 떠났다 돌아왔을 때, 효과음·음악을 껐을 때도 전과 같이 동작하는 것을 확인했습니다.
