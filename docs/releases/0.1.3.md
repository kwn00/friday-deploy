# v0.1.3

## 달라진 점

- **순위표에 각자 가지고 있던 무기·패시브가 나옵니다.** 판이 끝날 때(먼저 쓰러진 사람은 쓰러질 때) 가지고 있던 무기와 패시브를 아이콘과 단계로 보여줍니다. 순서는 게임 화면의 칸과 같습니다 (무기 먼저, 그다음 패시브).
- 함께 한 판은 사람마다 한 줄씩, 이름과 함께 보여줍니다.
- 이 버전 전에 세운 기록에는 남아 있는 값이 없어서 비워 둡니다.

## 내부 변경

- **값은 서버가 기록합니다.** 판이 끝날 때 서버가 가진 캐릭터 상태(`up`)에서 사람별 목록(`itemsBy`)을 만들어 리더보드에 넘깁니다. 클라이언트가 보내는 값은 없습니다. 기여도 순으로 이름을 정렬할 때 아이템도 같은 사람을 따라갑니다. 쓰러진 뒤에는 경험치를 얻지 못하므로 목록이 거의 바뀌지 않지만, 쓰러지기 전에 뜬 레벨업 선택지를 쓰러진 뒤에 고르면 그 하나는 들어갑니다.
- **걸러 내는 규칙 하나** (`packages/shared/src/content.ts` `ownedUpgrades`): 기록할 때, DB 에서 읽을 때, 클라이언트가 응답을 받을 때 같은 규칙으로 아는 아이템, 범위 안의 단계, 칸 수(무기 6 · 패시브 6) 안의 것만 남깁니다 (`docs/SECURITY.md` 에 반영).
- **DB 에 열 추가**: `leaderboard_runs.member_items` (jsonb). 서버가 뜰 때 열이 없을 때만 더하고, 기존 행은 건드리지 않습니다 (예전 기록은 NULL). 열을 더할 때 테이블 잠금을 오래 기다리지 않는 것은 `member_kills` 와 같습니다.
- **응답 크기**: `/api/leaderboard` 응답에 사람별 아이템이 붙습니다. 50줄이 모두 12칸을 채운 경우로 계산하면 혼자 순위표가 약 5.5KB → 약 24KB, 4명이 함께 한 순위표가 약 8.7KB → 약 81KB 입니다. 순위표는 열 때만 받고, 같은 순위표를 15초 안에 다시 열면 받지 않습니다.
- 리더보드 시즌과 통신 규격 버전은 그대로입니다 (순위 기준과 WebSocket 메시지는 바뀌지 않았습니다).

## 확인한 것

- 단위 테스트 통과 (PostgreSQL 테스트 포함). 새로 추가: 걸러 내는 규칙, 리더보드 정렬과 예전 기록, 방에서 넘기는 값, DB 저장·불러오기와 열이 없던 테이블.
- 실제 서버와 PostgreSQL 을 띄우고 실제 브라우저(Chromium)로 혼자 한 판을 끝까지 해서, 기록이 DB 와 순위표에 아이템과 함께 남고 서버를 다시 띄운 뒤에도 그대로 불러오는 것, 예전 형식의 기록은 비어 보이는 것을 확인했습니다.
- 순위표 화면을 320×568 · 390×844 · 844×390 · 1280×800 에서 확인했습니다 (함께 탭은 4명 × 12칸인 응답을 넣어서).
