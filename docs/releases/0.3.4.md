# v0.3.4

## 달라진 점

- **레벨업 선택지 새로고침.** 레벨업 카드가 마음에 들지 않으면 선택창의 🔄 F5 버튼으로 카드를 새로 뽑을 수 있습니다.
  - 한 판에 두 번까지입니다 (레벨업마다가 아니라 한 판 전체에서). 함께 하기에서는 사람마다 두 번씩입니다. 남은 횟수는 버튼에 나옵니다 (`새로고침 · 2번 남음`, 다 쓰면 `새로고침을 다 썼어요`).
  - 새로 뽑으면 지금 보이는 카드는 빼고 레벨업과 같은 규칙으로 다시 뽑습니다: 칸(무기 6 · 패시브 6), 최대 단계, 진화한 무기 제외, 가진 것을 먼저 넣는 굴림, 나오기 쉬운 정도(rarity). 카드 수는 그대로입니다 (배포 기도로 4장이었으면 4장). 새로 나올 것이 모자라면 지금 카드로 채웁니다.
  - 올릴 수 있는 것이 이미 다 나와 있으면 새로고침할 수 없고(`새로 나올 카드가 없어요`), 횟수도 줄지 않습니다.
  - 새로 뽑으면 고를 시간 20초를 처음부터 다시 셉니다.
  - 버튼은 카드 아래에 있고, 가로로 든 휴대폰처럼 세로가 낮은 화면에서는 선택창 왼쪽 위 구석(오른쪽 위 Ⅱ 버튼의 맞은편)에 있습니다.

## 내부 변경

- **판정은 서버가 합니다** (`packages/shared/src/sim.ts`): 남은 횟수(`Player.rerolls`, `OFFER_REROLLS` = 2)와 새 선택지는 서버의 시뮬레이션이 정합니다. 새 함수 `rerollOffers`, `canReroll`. 레벨업 선택지를 뽑던 `checkLevelUp` 을 `offerPool`(나올 수 있는 것) · `drawOffers`(뽑기) · `shuffleOffers`(순서 섞기)로 나눠 새로고침과 같이 씁니다. 비밀 난수를 쓰는 순서는 그대로라서, 같은 난수에서 레벨업 선택지는 예전과 같습니다. 새로고침도 비밀 난수만 씁니다.
- **통신** (`protocol.ts`, 통신 규격 버전 11 → 12): 클라이언트 메시지 `{ t: 'reroll', level }` 를 더했습니다. `level` 은 어느 선택지를 새로고침하는지(서버가 `levelup` 에 실어 준 레벨)만 가리킵니다: 선택 시간이 다 되어 서버가 대신 고르고 다음 레벨업으로 넘어간 뒤에 늦게 도착한 새로고침이, 아직 보지 못한 다음 선택지에 쓰이지 않게 합니다. `levelup` 에는 `level`, `rerolls`(남은 수), `rerollable`(지금 새로고침하면 다른 카드가 나올 수 있는지)을 더했습니다.
- **방** (`apps/server/src/room.ts`): `onReroll` 은 선택 중이 아니거나, 레벨이 다르거나, 횟수를 다 썼거나, 새로 나올 것이 없으면 아무것도 바꾸지 않습니다. 이때는 위반으로 치지 않고, 화면이 새 카드를 기다리며 멈춰 있지 않게 지금 선택지를 다시 보냅니다. 다시 보내는 것은 같은 선택지에 한 번뿐이라서, 혼자 하기를 멈춰 둔 채 요청을 쏟아부어도 서버가 보내는 양이 늘지 않습니다. 멈춰 둔 동안의 새로고침은 틱을 기다리지 않고 바로 답합니다. 다시 연결하면 남은 수와 함께 지금 선택지를 받습니다.
- **화면** (`main.ts`, `index.html`, `style.css`, `net.ts`): 새로고침을 누르면 새 카드가 올 때까지 지금 카드를 누를 수 없습니다 (서버는 받은 순서대로 처리하므로, 그 사이에 누른 카드 번호는 아직 보지 못한 새 카드에 쓰입니다). 두 번 누르기(두 번 탭)의 두 번째와, 선택지가 새로 뜬 뒤 0.4초 안의 누르기는 받지 않습니다 (답이 빨리 오면 두 번째 누르기가 방금 온 새 카드에 쓰여 두 번을 한꺼번에 쓰게 됩니다). 새로고침의 답(같은 레벨)에는 레벨업 소리를 다시 내지 않고, 레벨이 바뀌었으면 창이 떠 있어도 소리를 냅니다. 키보드로 누르면 답이 온 뒤 초점을 버튼(다 썼으면 첫 카드)으로 돌려놓는데, 그사이 메뉴를 열었으면 메뉴의 초점을 뺏지 않습니다. 메뉴가 열려 있는 동안 뒤에 가려진 선택창은 `inert` 라서 Tab·Enter 로 카드나 새로고침에 닿지 않습니다 (예전에는 Tab 으로 가려진 카드를 골라 멈춘 채로 고를 수 있었습니다). 멈춰 있는 동안 온 선택지의 남은 시간은 멈춘 때부터 세서 서버의 시간과 맞춥니다. 답 없이 선택창이 닫히면(시간이 끝남, 판이 끝남, 다시 연결) 기다리던 상태도 지웁니다. 서버가 보낸 남은 수는 모양을 확인하고 `textContent` 로 넣습니다.
- **통계**: `offered`(선택지에 나온 횟수)에는 새로고침으로 새로 나온 카드도 더합니다. 새로고침 뒤에 그대로 남은 카드는 한 번만 셉니다.
- 처음 화면을 받을 때 gzip 기준 약 0.5kB 가 늘었습니다 (JS 48.46 → 48.81kB, CSS 5.21 → 5.31kB, HTML 3.25 → 3.28kB). 서버 계산량은 새로고침할 때 선택지를 한 번 더 뽑는 것뿐입니다.
- 문서: README (장르 소개, 경험치·레벨업, 통계의 `offered`), docs/SECURITY.md (`reroll` 메시지와 새로고침 남용에 대한 대응).
- 리더보드 시즌과 기록 형식은 그대로입니다. 지운 기록은 없습니다.

## 확인한 것

- 타입 검사, 클라이언트 빌드, DB 없이 돌린 단위 테스트 304개 통과.
  - 새 테스트 (`reroll.test.ts` 10개, `room.test.ts` 3개): 한 판에 두 번(다음 레벨업에도 이어짐), 지금 카드가 다시 나오지 않음, 카드 수(4장 포함), 모자랄 때 채우기, 새로 나올 것이 없으면 받지 않고 횟수도 그대로, 칸·최대 단계·진화한 무기, 통계, 보이는 난수를 쓰지 않음, 제한 시간이 처음부터, 함께 하기에서 사람마다 따로, 메시지 형식, 서버가 대신 고른 뒤 늦게 온 새로고침, 같은 선택지에 한 번만 답하기, 다시 연결.
  - 서버 코드를 일부러 틀리게 바꾸면 테스트가 실패하는 것을 확인했습니다: 레벨 확인을 뺐을 때, 받지 않은 새로고침에 답하지 않을 때, 한 번만 답하는 표시가 새 선택지에서 풀리지 않을 때.
- 실제 서버에 WebSocket 으로 붙어 혼자 하기를 했습니다: 레벨업 전의 새로고침은 아무 답도 없고, 두 번 새로고침하면 다른 카드가 오고 남은 수가 2 → 1 → 0 이 되고, 다 쓴 뒤 50번 보내면 지금 선택지가 한 번만 다시 오고 연결은 유지되며, 그 뒤의 새로고침(지난 레벨을 가리킨 것 포함)과 형식이 틀린 새로고침에는 답하지 않습니다.
- 실제 서버와 실제 브라우저(Chromium)로 혼자 하기를 했습니다: 새로고침할 때마다 겹치지 않는 카드가 오고, 버튼 글자가 `2번 남음` → `1번 남음` → `다 썼어요`(꺼짐)로 바뀌고, 남은 시간이 20초로 돌아가고, 누르는 순간 카드가 잠기고, 마지막에 고른 카드가 장비 칸에 들어가고, 같은 판의 다음 레벨업에도 남은 수가 이어집니다. 페이지를 새로 고쳐도 같은 카드와 남은 수가 돌아옵니다. 콘솔 오류는 없습니다.
- 함께 하기를 브라우저 두 개로 했습니다: 한 사람이 새로고침해도 다른 사람의 남은 수는 그대로입니다.
- 서버의 답을 200ms 늦춘 브라우저로: 두 번 누르기는 새로고침 한 번만 보냅니다. 키보드로 새로고침하고 바로 메뉴를 열면 초점이 메뉴의 계속하기에 남고, Tab 이 가려진 선택창에 닿지 않고, 메뉴 동안 아무것도 보내지 않습니다. 멈춰 있는 동안 남은 시간은 20초에 머물다 다시 움직이면 줄어듭니다.
- 선택창을 320×568 · 390×844 · 480×320 · 520×320 · 559×320 · 568×320 · 640×360 · 844×390 · 915×412 · 1280×800 에서 카드 3장과 4장으로 쟀습니다 (4장은 화면에서 카드를 하나 복제해 만들었습니다). 버튼이 화면과 선택창 안에 있고, 카드·제목·안내 글자·Ⅱ 버튼과 겹치지 않고, 가로 스크롤이 없습니다. 가장 긴 문구(`새로 나올 카드가 없어요`)로도 쟀습니다.
