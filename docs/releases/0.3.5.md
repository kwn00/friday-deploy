# v0.3.5

## 달라진 점

- **🧲 자석.** 맵 어딘가에 자석이 가끔 떨어집니다. 주우면 그 순간 땅에 있는 경험치가 거리와 상관없이 모두 주운 사람에게 끌려옵니다.
  - 피자·LGTM·백업과 따로 평균 180초에 하나 놓입니다 (108~252초 간격). 놓이는 자리(화면 밖 500~800px)와 수명(90초, 사라지기 10초 전부터 깜빡임)은 다른 필드 아이템과 같고, 맵에는 하나까지 있습니다. 피자·LGTM·백업의 자리(3개)를 차지하지 않아서 그것들이 덜 나오지는 않습니다.
  - 주울 때 땅에 있던 것만 끌어당깁니다. 나중에 떨어지는 경험치는 평소대로입니다.
  - 끌려오는 경험치는 주운 사람이 레벨업을 고르는 동안 그 자리에서 기다렸다가 이어서 옵니다 (rm -rf node_modules 와 같은 규칙). 경험치가 많으면 레벨이 여러 번 연달아 오릅니다.
  - 떨어지면 `🧲 자석이 떨어졌어요! 주우면 경험치가 모두 끌려와요` 가 뜨고, 화면 밖이면 화면 가장자리의 화살표와 미니맵(진한 빨간 말굽)이 자리를 알려 줍니다. 주우면 자석 소리와 함께 `🧲 자석! 경험치 37개가 끌려와요` 처럼 몇 개가 오는지 알려 줍니다.
  - 🧹 git clean 이 지우는 쪽이 나오면 화면 안의 자석도 다른 필드 아이템처럼 지워집니다.
- **함께 하기의 자석.** 동료가 자석을 주우면 내 근처의 경험치도 그 동료에게 날아갑니다. 그래서 방의 모두에게 `🧲 ○○ 님이 자석을 주웠어요! 경험치가 모두 그쪽으로 끌려가요` 로 알립니다.
  - 동료가 지금 끌어당기고 있는 경험치는 그대로 두고, 동료가 레벨업을 고르느라 기다리게 해 둔 경험치는 내 자석이 가져옵니다.
  - 고르지 않아 시간(20초)이 다 되어 자동으로 골라지면, 그 사람을 기다리던 경험치는 그 자리에 놓여 누구나 주울 수 있습니다 (자리를 비운 사람 때문에 맵의 경험치가 묶이지 않게). 혼자 하기는 고르는 동안 게임이 멈춰 있으므로 놓지 않습니다.
- **강화를 모두 마친 뒤의 레벨업은 체력을 가득 채웁니다.** 무기 6칸·패시브 6칸이 모두 차고 모두 최대 단계가 되면, 레벨업할 때 선택지 대신 체력이 가득 찹니다 (예전에는 피자 하나만큼, 30). `❤️ 레벨 업! 체력을 가득 채웠어요 (+42)` 처럼 찬 양을 알려 주고 회복 소리가 납니다. 이미 가득이면 아무 일도 없습니다.
  - 이때 여는 보물상자는 예전처럼 한 칸에 피자 하나만큼 회복합니다.
- **알림.** 좁은 화면에서 긴 알림이 4줄로 보이던 것이 2줄로 줄었습니다 (320px 폭의 자석 알림, 보물상자 알림 등). 자석·체력 채우기 알림은 30분의 월요일 아침 경고와 동료의 연결 소식을 덮지 않습니다.

## 고친 것

- 알림의 폭이 화면 폭의 절반에 묶여 있었습니다 (가운데 맞춤을 `left: 50%` 와 `translate` 로 해서, 줄바꿈 폭이 남은 절반이 되었습니다). 이제 양쪽을 0 으로 두고 내용만큼의 폭(최대 화면 폭 - 24px)을 가운데에 놓습니다.
- 한꺼번에 여러 아이템이 새로 놓였을 때 알릴 것을 고르는 기준이, 놓일 때의 비중이 작은 것(드문 것)이었습니다. 비중 0 은 "따로 놓는다"는 뜻이라(보물상자, 자석) 드문 정도로 쓸 수 없어서, 정한 순서(보물상자 > 백업 > 자석 > LGTM > 피자)로 바꿨습니다.

## 내부 변경

- **시뮬레이션** (`packages/shared/src/sim.ts`):
  - 필드 아이템 종류 `magnet` 을 `FIELD_ITEM_KINDS` 의 맨 뒤에 더했습니다 (통신 번호 4. 예전 번호는 그대로). 놓일 때의 비중은 0 이고, 따로 센 시간 `World.magnetCd` 가 놓습니다 (`MAGNET_INTERVAL` = 180, `MAX_MAGNETS` = 1, `constants.ts`). 시간·자리 모두 비밀 난수만 씁니다: 보이는 난수(적 스폰 등)를 쓰는 횟수는 자석과 상관없습니다. 월드를 만들 때 비밀 난수를 한 번 더 쓰므로, 같은 시드에서 비밀 난수로 정하는 것(선택지, 상자)은 예전과 다르게 나옵니다.
  - `pullAllGems`: 땅의 모든 경험치를 주운 사람에게 (`to`, `hold`). 다른 살아 있는 사람이 지금 끌어당기는 것은 건너뛰고, 그 사람이 고르는 중이라 기다리는 것과 쓰러진·나간 사람이 끌던 것은 가져옵니다.
  - `releaseHeld`: 함께 하는 판에서 선택 시간이 다 되어 서버가 대신 고르면(`pickOffer` 의 `auto`) 그 사람을 기다리던 경험치의 `to`·`hold` 를 지웁니다. 검토 중에 고르지 않는 사람 하나가 400개 중 118개를 200초 넘게 묶어 두는 것을 재서 넣었습니다.
  - `refill`: 선택지에 나올 것이 없을 때(`offerPool` 이 비었을 때) `heal` 대신 최대 체력으로. 화면에 보이는 체력(올림)이 이미 가득이면 아무것도 하지 않습니다.
  - 새 월드 이벤트 `magnet`(주운 사람, 새로 끈 수), `refill`(찬 양).
- **통신** (`protocol.ts`, 통신 규격 버전 12 → 13): 서버 → 클라이언트 메시지 `{ t: 'magnet', by, gems }`(방의 모두에게), `{ t: 'refill', hp }`(채워진 사람에게만)를 더했습니다. 화면의 알림용이고, 끌어당기기와 체력은 서버가 계산해 스냅샷으로 보냅니다. 클라이언트가 보내는 메시지는 그대로입니다. 예전 화면은 처음 연결할 때 `version_mismatch` 를 받아 새로고침하라는 안내를 봅니다 (예전 화면은 종류 번호 4 를 모르므로 이진 스냅샷 형식은 그대로 두고 규격 버전으로 막았습니다).
- **방** (`apps/server/src/room.ts`): 새 이벤트를 위 메시지로 보냅니다. 연결이 끊겨 있으면 보내지 않습니다 (다시 붙으면 스냅샷이 결과를 보여 줍니다).
- **화면**: 자석 그림(`art.ts`, 빨간 말굽에 은색 끝), 받침 빛과 주울 때의 반짝임(`render.ts`), 화면 가장자리 표시와 미니맵의 말굽 표시(적의 분홍 점과 다른 진한 빨강, `minimap.ts`), 자석 소리(`sounds.ts`, `sound-cues.ts`), 알림 문구(`alerts.ts`: 서버가 보낸 숫자와 동료 이름은 모양을 확인하고 `textContent` 로 씁니다). 알림의 폭(`style.css` 의 `.hud__note--toast`)과 덮어쓰기 규칙(`main.ts` 의 `toast`).
- **주석**: 경험치를 기다리게 하는 규칙(`hold`, `mergeHeld`)과 땅이 가득할 때의 처리에 자석을 더했습니다.
- 처음 화면을 받을 때 gzip 기준 약 0.9kB 가 늘었습니다 (JS 48.81 → 49.66kB, CSS 5.31 → 5.34kB, HTML 3.28kB 그대로).
- 문서: README (칸·단계, 미니맵, 필드 아이템, 경험치 끌어당기기, 알림, 소리, 보안 요약, 로드맵), docs/SECURITY.md (맵핵 행의 예외, 필드 아이템 행, 새 행: 자석으로 동료의 경험치 묶어 두기).
- 리더보드 시즌과 기록 형식은 그대로입니다. 지운 기록은 없습니다.

## 확인한 것

- 타입 검사, 클라이언트 빌드, DB 없이 돌린 단위 테스트 322개 통과.
  - 새 테스트 (`magnet.test.ts` 12개, `alerts.test.ts` 4개, `room.test.ts` 1개, `sound-cues.test.ts` 1개): 놓이는 간격·거리·수명·한 번에 하나, 비밀 난수만 쓰기, 맵 전체 끌어당기기(4000px 밖까지)와 나중에 떨어진 것, 다른 사람이 끌던 것, 동료가 고르는 동안 기다리기와 내 자석으로 가져오기, 시간이 다 되면 놓기(혼자는 그대로), 주운 사람이 쓰러졌을 때, 다른 아이템의 수에 세지 않기, 스냅샷, 체력 가득 채우기(한 번에 여러 레벨, 이미 가득일 때), 알림 메시지가 가는 사람, 알림 문구와 순서, 자석 소리. git clean 테스트에 자석을 더했고, 진화 뒤 강화를 모두 마친 레벨업 테스트는 체력이 가득 차는지를 봅니다.
  - 서버 코드를 일부러 틀리게 바꾸면 테스트가 실패하는 것을 확인했습니다: 고르는 중인 사람을 기다리는 경험치를 건너뛸 때, 시간이 다 되어도 놓지 않을 때, 혼자 하기에서도 놓을 때, 자석이 이미 있어도 놓을 때, 자석을 다른 아이템의 수에 셀 때, 예전처럼 30만 회복할 때, 기다리게 하지 않을 때.
- 봇으로 밸런스를 쟀습니다 (서버 없이 시뮬레이션, 0.3.4 와 자석 간격 120·180·300초, 원을 그리는 봇 100판, 아이템을 찾아가는 봇 200판, 아이템과 경험치를 찾아다니며 적을 피하는 봇 200판씩).
  - 180초: 어느 봇도 생존 시간이 의미 있게 늘거나 줄지 않았습니다 (평균 −2% ~ +5%, 잡음 범위 안). 경험치를 찾아다니는 봇은 자석을 한 판에 약 3번 주웠고, 얻은 경험치의 25% 가 자석에서 왔고, 레벨은 5분에 11 → 14, 10분에 20 → 24 였습니다.
  - 120초: 아이템을 찾아가는 봇의 생존 시간이 평균 8.5% 줄었고(자석을 쫓다 쓰러짐), 맵에 하나뿐이라 건너뛰는 차례가 생겼습니다. 300초: 첫 자석이 5분쯤에야 나와서 짧은 판에서는 대부분 보지 못했습니다.
  - 강화를 모두 마치는 일은 30분 동안 거의 없었고(200판 중 1~6판), 최대 장비로 20분부터 시작한 봇에서는 체력 가득 채우기가 한 판에 1.3~1.5번, 합쳐서 약 100 을 채웠습니다 (예전 규칙보다 약 57 더).
- 전송량과 서버 계산량을 쟀습니다.
  - 시뮬레이션: 땅에 경험치 400개를 3000px 안에 흩어 두고 자석을 주우면, 스냅샷이 약 6초 동안 커졌다가 돌아옵니다 (10초 동안 한 사람에게 약 25kB 더). 실제로 경험치를 찾아다니는 봇의 판에서는 자석 때문에 늘어난 전송량을 잴 수 없을 만큼 작았습니다.
  - 실제 서버에 WebSocket 봇으로 0.3.4 와 이 버전(검토를 반영하기 전의 코드)을 혼자 하기로 2판씩 했습니다: 한 판의 전송량(초당 9.9~15.6kB)과 서버 계산량(코어 하나의 1.5~1.7%)이 같은 범위였고, 자석은 두 판 모두 처음 놓일 수 있는 시간 안(181초, 231초)에 화면 밖 650~710px 에 놓였고, 주우면 화면 밖의 것까지 234개·123개가 끌려왔습니다 (첫 판에서는 2초쯤 안에 화면을 지나 먹혔습니다). 서버 기록에 오류가 없었습니다. 규격 12 로 연결하면 `version_mismatch` 로 닫히고 13 은 들어갑니다.
- 실제 브라우저(Chromium)로 320×568 · 568×320 · 390×844 · 844×390 · 1280×800 에서 자석이 떨어지고(알림, 화면 가장자리 표시, 미니맵), 화면 안에 보이고, 주워서 경험치가 몰려오고, 강화를 모두 마친 뒤 레벨업해 체력이 가득 차는 것을 봤습니다 (자석 간격을 줄이고 최대 장비로 시작하게 고친 서버 사본으로. 알림 폭과 색을 고친 뒤 다시 봤습니다). 알림이 잘리거나 HUD 와 겹치지 않고, 가로 스크롤이 없고, 콘솔 오류가 없습니다. 가장 긴 자석 알림은 320·390px 폭에서 2줄, 가로 화면과 데스크톱에서 1줄입니다. 동작 줄이기 설정에서도 봤습니다.
