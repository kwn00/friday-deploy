# Friday Deploy (금요일 배포)

> 금요일 저녁 배포에서 살아남기

개발자 컨셉의 픽셀아트 서바이버(로그라이트 호드 서바이벌) 웹 게임.
버그·NullPointerException·Merge Conflict·기술 부채가 몰려오는 금요일 저녁, `console.log()` 하나 들고 월요일 아침이 올 때까지 30분을 버티세요.

- **장르**: 자동 공격 서바이버 (이동만 조작, 레벨업 시 3택 1)
- **플랫폼**: 웹 (모바일 퍼스트, 적응형 캔버스 + 반응형 UI)
- **멀티**: 서버 권위 구조. 현재 솔로 + 최대 4인 co-op 방(β) 뼈대 포함
- **아트**: 외부 이미지 없이 코드로 구운 픽셀 스프라이트

콘텐츠는 전부 `packages/shared/src/content.ts` 한 파일에 데이터로 정의되어 있어 쉽게 추가할 수 있습니다.

## 구조

```
packages/shared   프로토콜 · 메시지 검증 · 콘텐츠 정의 · 결정론적 시뮬레이션 (서버/클라 공용)
apps/server       Node + ws. 권위 서버: 게임 루프, 방(Room), 세션, 레이트리밋, 정적 파일 서빙
apps/client       Vite + TypeScript + Canvas 2D. 입력 전송과 렌더링만 담당
docs/SECURITY.md  치팅 방지 설계와 위협 모델
```

```
[Client]  입력 의도(dx, dy / 선택지 번호)  ──▶  [Server] 검증 → 시뮬레이션(20Hz)
[Client]  ◀── 내 시야 범위의 스냅샷 ──────────  [Server] 결과 계산 + 서명
```

## 조작

| | 키보드 | 터치 |
| --- | --- | --- |
| 이동 (공격은 자동) | WASD / 방향키 | 화면 아무 곳이나 드래그 |
| 일시정지 / 메뉴 | Esc 또는 P | 오른쪽 위 Ⅱ 버튼 |
| 미니맵 켜고 끄기 | M | 메뉴 안의 버튼 |
| 효과음 · 음악 켜고 끄기 | 메뉴 안의 버튼 | 메뉴 안의 버튼 (타이틀 왼쪽 아래 🔊 는 둘을 한꺼번에) |

- **혼자 하기**: 일시정지하면 서버의 게임 시간이 실제로 멈춥니다 (한 번에 최대 10분, 한 판에 합쳐서 30분. 탭을 떠나면 자동으로 멈춤).
- **페어 프로그래밍(최대 4명)**: `방 만들기` → 6자리 방 코드나 초대 링크를 공유 → 상대가 `코드로 참가` → 방장이 시작.
  진행 중인 판에도 같은 코드로 합류할 수 있고, 판이 끝나면 같은 방 대기실로 돌아와 바로 다시 시작할 수 있습니다.
- **관전**: 페어에서 쓰러지면 그 판이 끝날 때까지 관전합니다. 관전 중에도 조작으로 시점을 움직여 둘러볼 수 있습니다
  (내 화면에만 반투명한 유령으로 보이고, 살아 있는 동료 주변을 벗어나지는 못합니다. 동료에게는 쓰러진 자리의 묘비만 보입니다).
  그 판에서 누군가 쓰러졌거나 나간 뒤에 들어오는 사람은 — 쓰러졌거나 나갔다 다시 들어온 본인 포함 — 캐릭터 없이 관전으로 들어옵니다.
  다음 판에는 모두 다시 참가합니다. 계정이 없어 같은 사람인지 서버가 확인할 수 없으므로, 그런 판에는 처음 온 사람도 관전으로 들어옵니다.
  페어에서는 메뉴를 열어도 게임이 멈추지 않습니다 (한 사람이 다른 사람의 게임을 멈출 수 없습니다).
- **끊긴 연결 다시 붙기**: 연결이 끊겨도(다른 앱에 다녀왔거나, 와이파이가 바뀌었거나, 실수로 새로고침했을 때) 서버가 자리를 지켜 둡니다.
  화면이 스스로 다시 연결해서, 같은 캐릭터로 하던 판을 이어서 합니다.
  - 혼자 하기: 끊긴 동안 게임이 멈춥니다 (일시정지와 같은 한도: 한 번에 최대 10분). 돌아오면 메뉴가 떠 있고, 계속하기를 누르면 이어집니다.
  - 함께 하기: 게임은 멈추지 않고, 캐릭터는 그 자리에 서서 계속 맞습니다 (동료에게는 이름 옆에 💤 로 보입니다).
    2분 안에 돌아오면 같은 캐릭터로 이어서 하고, 2분이 지나면 자리가 비워져 같은 방에 코드로 다시 들어갑니다 (진행 중인 판이면 그 판은 관전).
  - 대기실: 대기실이 닫힐 때까지 자리를 지킵니다 (초대 링크를 보내러 다른 앱에 다녀와도 됩니다).
    방장의 연결이 끊겨 있는 동안에는 접속해 있는 사람이 시작할 수 있고, 시작하면 끊긴 사람은 빼고 시작합니다 (돌아오면 코드로 다시 들어옵니다).
  - `나가기` · `그만두기`를 누르면 자리를 바로 비웁니다. 서버가 새로 시작되면(배포 등) 이어갈 수 없습니다.
- **미니맵**: 화면 밖에서 다가오는 적, 떨어진 회복 아이템(야근 피자 🍕), 멀어진 동료의 방향을 보여줍니다.
  필드 아이템은 멀리 있어도 표시됩니다: 범위 밖이면 가장자리에 붙어 방향을 알려주고, 새로 놓인 것은 잠깐 테두리가 퍼집니다
  (🍕 초록 십자 · ✅ 노란 마름모 · 💾 하늘색 네모).
- **필드 아이템**: 적을 잡지 않아도 맵 어딘가에 아이템이 가끔 놓입니다 (평균 110초에 하나, 화면 밖 500~800px, 동시에 최대 3개, 90초 뒤 사라짐).
  - 🍕 **야근 피자**: 체력 30 회복 (워라밸이 있으면 더)
  - ✅ **LGTM**: 즉시 1레벨 업 (강화 선택지가 바로 뜹니다)
  - 💾 **백업**: 아주 드물게 나옵니다. 가지고 있으면 쓰러질 순간에 그 자리에서 체력 절반으로 되살아나고, 2초 동안 피해를 받지 않습니다 (하나만 가질 수 있음)
- **피격 표시**: 공격이 맞은 적은 하얗게 번쩍입니다. 무기에 따라 실제로 잠깐 밀려나기도 합니다 (넉백: 서버가 계산).
  기기의 "동작 줄이기" 설정이 켜져 있으면 번쩍임만 보여줍니다.
- **닉네임**: 모든 캐릭터 머리 위에 닉네임이 뜹니다 (나는 초록, 동료는 흰색, 쓰러진 사람은 묘비 위에 회색).
- **경험치 끌어당기기**: 획득 범위 안에 들어온 경험치(커밋)는 그 자리에서 사라지지 않고 캐릭터에게 빨려 들어와 닿을 때 획득됩니다.
  `npm install` 을 올리면 끌어당기는 범위가 넓어집니다. 위치는 서버가 계산합니다 (범위는 예전의 획득 범위와 같습니다).

## 리더보드

판이 끝나면 **서버가 직접** 기록을 순위표에 올립니다. 클라이언트가 점수를 보내는 요청은 없어서, 점수를 꾸며서 올릴 방법이 없습니다.

- 순위표는 두 개: **혼자** 한 판 / **함께** 한 판 (판이 진행되는 동안 2명 이상이 같이 있었던 판).
  페어 방에서 혼자 한 판은 혼자 순위표로 갑니다 (대기실에만 있다 나간 사람은 세지 않습니다)
- 순위: 오래 버틴 순 → 많이 잡은 순 → 레벨 높은 순 → 먼저 세운 기록 순. 상위 50개를 보여줍니다
- 30초 미만으로 끝난 판은 기록하지 않습니다
- 함께 한 판은 기여도(개인 처치 수)가 큰 사람부터 이름을 적고, 이름 옆에 각자의 기여도(%)를 보여줍니다.
  값은 서버가 센 것입니다. 이 표시를 넣기 전의 기록은 이름만 보입니다.
- 사람마다 판이 끝날 때(쓰러졌으면 쓰러질 때) 가지고 있던 무기·패시브를 아이콘과 단계로 보여줍니다.
  값은 서버의 캐릭터 상태에서 가져옵니다. 이 표시를 넣기 전의 기록은 비워 둡니다.
- 함께 한 판에는 처음부터 끝까지 있던 사람의 이름만 오릅니다 (도중에 들어온 사람, 관전한 사람은 제외).
  순위가 없을 때는 결과 화면이 이유를 알려줍니다 (너무 짧은 판 / 도중 합류 / 순위표 밖)
- **시즌 = 버전의 메이저**(`x.y.z` 의 `x`). 지금은 0.x 이므로 **시즌 0** 입니다. 그 전 규칙으로 쌓인 기록(시즌 1~3)은 모두 시즌 0 으로 합쳤습니다 (지운 기록은 없습니다).
  시즌을 바꾸는 것은 메이저 버전을 올리는 것이고, 그러면 새 순위표로 시작합니다. 지난 시즌의 기록은 지우지 않고, 아래 API 로 볼 수 있습니다
- **되돌리기(롤백) 주의**: 시즌 0 으로 합친 뒤에 이 기능이 들어가기 전의 배포(0.2.2 이하, 시즌 3 을 읽는다)로 되돌리면, 그동안은 순위표가 비어 보입니다.
  기록은 지워지지 않고 DB 에 그대로 있으며, 이 기능이 들어간 배포로 다시 올리면 되돌린 동안의 기록까지 모두 보입니다.
  되돌려야 하면 이 기능이 들어간 배포 중에서 고르세요. 0.x 로 되돌려도 새 규칙의 시즌 1 이상 기록은 건드리지 않습니다
- 기록은 지우지 않습니다 (예전에는 순위표마다 1000개 밖의 기록을 자동으로 지웠지만 없앴습니다)
- 저장하는 것은 닉네임, 기록, 끝난 시각뿐입니다 (IP 주소 등은 저장하지 않습니다)

기본 상태에서는 기록이 **서버 메모리에만** 있어서 서버가 다시 시작되면(배포, 무료 서버가 잠들었다 깨어날 때) 사라집니다.
기록을 유지하려면 아래 [기록 유지하기](#기록-유지하기-선택) 를 설정하세요.

## 공개 API (통계)

누구나 읽을 수 있는 JSON 입니다 (GET, 다른 사이트에서도 읽을 수 있음). 이름·IP 같은 개인 정보는 순위표에 이미 보이는 닉네임 말고는 없습니다.
`season` 을 빼면 지금 시즌이고, 없는 시즌이면 `404` (`{"error":"unknown_season","seasons":[...]}`), 숫자가 아니면 `400`, 저장소를 읽지 못해 지난 시즌을 확인할 수 없으면 `503` (`Retry-After`) 입니다.
지금 시즌은 서버 메모리에서 바로 답합니다 (DB 가 느리거나 죽어 있어도 기다리지 않습니다).

| URL | 내용 |
| --- | --- |
| `/api/leaderboard?board=solo\|coop&season=N` | 순위표 (상위 50). `season`(보고 있는 시즌), `current`(지금 시즌), `seasons`(기록이나 통계가 있는 시즌들), `entries` (기록마다 세운 게임 버전 `version`, 버전을 남기기 전의 기록은 없음) |
| `/api/stats/upgrades?season=N&version=x.y.z&kind=weapon\|passive` | 아이템 통계. `version` 을 빼면 시즌 전체(모든 버전의 합), `kind` 를 빼면 무기·패시브 모두 |

아이템 통계 (`/api/stats/upgrades`) 의 주요 값:

- **게임 버전별로 쌓습니다** (같은 시즌 안에서 밸런스 패치 전후를 나눠 볼 수 있게). `version`(보고 있는 버전, 시즌 전체면 `null`), `currentVersion`(지금 서버의 버전),
  `versions[]`(이 시즌에 통계가 있는 버전과 각 `runs`·`since`, 최신 버전부터. 지금 시즌에는 지금 버전이 판이 없어도 `runs: 0` 으로 들어 있다).
  없는 버전이면 `404` (`{"error":"unknown_version","versions":[...]}`), 형식이 틀리면 `400` (`bad_version`).
  서버가 막 깨어나 저장된 통계를 아직 못 불러왔으면, 지금 버전이 아닌 버전은 있는지 알 수 없어 `503` (`Retry-After`) 으로 답합니다
  버전을 붙이기 전에 쌓인 몫(0.2.2 에서 센 판)은 0.2.2 로 보입니다
- `runs`: 센 판 수. 리더보드와 같은 판(30초 이상, 처음부터 함께 한 사람)을 **사람마다 하나**로 셉니다. `since`: 세기 시작한 날 (UTC)
- `upgrades[]`: 모든 무기·패시브, 선택률 높은 순
  - `offered` 레벨업 선택지에 나온 횟수 · `picked` 직접 고른 횟수 · `autoPicked` 시간이 지나 자동으로 골라진 횟수
  - `pickRate` = (`picked` + `autoPicked`) / `offered` · `chest` 보물상자로 오른 횟수 (진화한 무기는 진화한 횟수: 보물상자로만 얻는다)
  - `evolve` 진화한 무기에만: `{ "from": ["console_log"], "with": "test_coverage" }` (재료 무기와 짝 패시브. 합치기는 `from` 이 둘이고 `with` 가 `null`)
  - `finalOwnedRate` 판이 끝날 때 가지고 있던 판의 비율 · `avgFinalLevel` 가지고 있던 판의 평균 단계
- `topRuns`: 그 시즌 순위 기록(순위표마다 상위 200개)의 끝날 때 아이템. `owned[]` 의 `rate`(가진 사람 비율)와 `avgLevel`. 버전을 고르면 그 버전에서 세운 기록만 (버전을 남기기 전의 기록은 빠짐)
- `persistent`(DB 에 쌓이는지), `loading`(지금 시즌의 저장된 통계 합계나 순위 기록을 아직 다 불러오지 못함: `runs`·`upgrades` 나 `topRuns` 가 일부일 수 있고, 캐시하지 않게 보낸다)

숫자는 모두 서버가 셉니다 (선택지를 만들고, 고르고, 시간이 지나 대신 고르고, 상자를 여는 것이 모두 서버의 일입니다). 지금 시즌은 서버 메모리의 합계로 답하고 1분 동안 캐시해도 된다고 알려 줍니다 (`loading` 이 `true` 인 응답은 캐시하지 않게 합니다).
통계는 이 기능을 넣은 날부터 쌓입니다 (그 전 판의 선택 기록은 없습니다). `topRuns` 는 0.1.3 부터의 순위 기록에서 계산합니다.

## 버전과 릴리즈

- 현재 버전은 타이틀 화면 오른쪽 아래 구석에 표시됩니다. 누르면 **새 소식**(그 버전에서 달라진 점)이 열립니다.
- 새 소식은 그 버전을 처음 보는 브라우저에 한 번 자동으로 뜨고, 같은 버전으로 다시 오면 뜨지 않습니다.
- 게임 안 새 소식에는 플레이어가 체감하는 것만 쉬운 말로 적습니다 (`packages/shared/src/releases.ts`).
  전체 변경 내역은 [GitHub 릴리즈](../../releases)에 있습니다 (`docs/releases/<버전>.md` 가 본문).
- 작업은 버전 브랜치 `release/x.y.z` 에서 하고, PR 을 승인·머지하면 태그와 GitHub 릴리즈가 자동으로 만들어집니다
  (`.github/workflows/release.yml`). 절차는 `.claude/skills/release/SKILL.md`, 작업 규칙은 `CLAUDE.md`.
- 배포된 서버의 버전은 `/healthz` 로 확인할 수 있습니다.

## 소리

소리 파일 없이 브라우저가 그 자리에서 만듭니다 (Web Audio). 내려받는 파일이 없어 전송량이 늘지 않고, 서버는 아무것도 하지 않습니다.

- **언제 나는지**: `apps/client/src/sound-cues.ts` — 화면이 받은 직전·지금 장면을 비교해서 정합니다 (적이 맞음·쓰러짐, 경험치·아이템을 먹음, 맞음, 쓰러짐, 되살아남, 보스 등장·처치, 30분). 화면의 반짝임과 같은 순간에 납니다.
  레벨업 · 강화 선택 · 판 시작 · 판 끝 · 버튼 소리는 `main.ts` 가 냅니다.
- **어떤 소리인지**: `apps/client/src/sounds.ts` — 효과음은 음(주파수·길이·크기)의 목록, 배경음악은 글자로 적은 악보입니다 (타이틀 곡, 게임 곡). 테마가 곡을 바꿀 수 있습니다 (크리스마스: 징글벨).
- **연주**: `apps/client/src/audio.ts`. 같은 소리가 너무 자주·많이 겹치지 않게 거르고, 메뉴나 선택창이 열려 있으면 음악을 줄이고, 화면을 떠나면 멈춥니다. 음악을 끄면 음을 만들지도 않습니다.
- 브라우저는 화면을 한 번 누르기 전에는 소리를 내지 못하게 하므로, 처음 누르는 순간부터 소리가 납니다.

## 테마 (계절·행사 스킨)

색·바닥·내리는 것(눈 등)·캐릭터 장식·타이틀 문구를 테마 하나로 묶어 두었습니다. 게임 규칙에는 영향이 없습니다.

- **바꾸기**: `packages/shared/src/theme.ts` 의 `ACTIVE_THEME` 한 줄 (`'christmas'` · `'default'`)
- **새로 만들기**: `THEME_IDS` 에 이름을 넣고 `apps/client/src/themes.ts` 의 `THEMES` 에 한 벌을 추가 (기본 테마를 펼쳐 놓고 바꿀 것만 덮어쓰기). 배경음악도 테마마다 바꿀 수 있습니다 (`music`)
- 화면에 입히는 것은 `apps/client/src/apply-theme.ts` 의 `applyTheme()` 입니다. 게임 중에 다시 불러도 되므로, 나중에 관리자 화면에서 고르면 서버가 내려준 값으로 부르기만 하면 됩니다.

## 배포

게임 서버는 20Hz 루프와 방 상태를 메모리에 들고 있어서, 서버리스(Vercel Functions)가 아니라
프로세스가 계속 살아 있는 곳이 맞습니다. 서버 한 프로세스가 화면 · API · WebSocket 을 모두 서빙하므로
**한 곳에 하나만 올리면 됩니다.**

### Render (기본, 무료)

설정은 [`render.yaml`](render.yaml) 에 있습니다.

1. [Render](https://render.com) 에 GitHub 계정으로 가입
2. **New → Blueprint** → 이 저장소 선택 → **Apply**
3. 빌드가 끝나면 `https://friday-deploy.onrender.com` (이름이 이미 쓰였다면 뒤에 접미사가 붙음) 으로 접속

`SESSION_SECRET` 은 Render 가 자동으로 만들고, 리전은 싱가포르로 고정됩니다. 이후 `main` 에 푸시하면 자동 배포됩니다.

무료 플랜에서 알아둘 것:
- 15분 동안 접속이 없으면 잠들고, 다음 접속 때 깨는 데 약 1분 걸립니다 (그동안 페이지도 뜨지 않음)
- 월 전송량 5GB (워크스페이스 전체). 화면 데이터를 작은 이진 형식으로 보내서 혼자 하는 15분이 약 10~31MB
  (15분짜리 판으로 치면 월 약 160~480판), 30분(월요일 아침)까지 다 버티면 약 25~67MB (월 약 75~200판)입니다
  (봇으로 잰 값). 화면 주변에 버그와 줍지 않은 커밋이 많이 쌓일수록 늘어납니다. 서버가 사람마다 따로 보내므로
  2인 페어는 15분에 약 18~42MB (15분짜리 판으로 치면 월 약 120~270판)입니다.
  카드 없이 한도를 넘으면 그 달 남은 기간 동안 서비스가 멈추고, 카드를 등록해 두면 멈추지 않는 대신 초과분이
  GB 당 약 $0.15 로 청구되며 상한이 없습니다. 대시보드 **Billing** 에서 사용량을 확인하세요.
- Render 가 무료 인스턴스를 임의로 재시작할 수 있어, 진행 중인 판이 가끔 끊길 수 있습니다
- 배포할 때마다 진행 중인 판은 끊깁니다
- 무료 플랜에는 계속 유지되는 저장소가 없습니다 (무료 Postgres 는 약 44일 뒤 삭제). 리더보드를 넣을 때
  `plan: starter` + 디스크로 올리거나 다른 호스트로 옮기세요.

### 기록 유지하기 (선택)

리더보드 기록을 유지하려면 PostgreSQL 주소를 환경 변수 `DATABASE_URL` 로 넣으면 됩니다. 코드는 바꿀 것이 없습니다.
Render 무료 플랜에는 계속 유지되는 저장소가 없으므로(무료 Postgres 는 약 44일 뒤 삭제), 무료로 하려면 외부의
무료 PostgreSQL 을 씁니다. [Neon](https://neon.tech) 은 한동안 안 쓰면 잠들었다가 요청이 오면 알아서 깨어나서 이 용도에 맞습니다.

1. [Neon](https://neon.com) 에 가입한다 (Google / GitHub 계정 또는 이메일)
2. **New Project** → 이름을 적고, Region 은 Render 서버와 같은 **AWS Asia Pacific (Singapore)** 를 고른 뒤 **Create project**
   (리전은 나중에 바꿀 수 없다. Postgres 버전은 기본값 그대로)
3. 프로젝트 화면의 **Connect** 를 눌러 나오는 연결 문자열을 **비밀번호가 포함된 채로** 복사한다
   (`postgresql://neondb_owner:...@ep-...ap-southeast-1.aws.neon.tech/neondb?sslmode=require...` 형태)
4. Render 대시보드 → 서비스 → **Environment** → 환경 변수 추가: Key `DATABASE_URL`, Value 에 복사한 문자열 →
   **Save, rebuild, and deploy**
5. 배포가 끝나면 게임의 리더보드 화면을 연다. "기록은 서버 메모리에 있어서 … 사라져요" 안내가 없으면 된 것이다

연결 문자열은 기본으로 나오는 풀링 주소(호스트 이름에 `-pooler`)와 **Connection pooling** 을 끈 직접 주소 모두 쓸 수 있습니다.

연결은 TLS 로 하고 인증서 검증도 켜 둡니다 (`sslmode=require` 그대로 두면 됩니다. 로그에 pg 의 안내 문구가 한 번 찍히는데,
`sslmode=verify-full` 로 바꾸면 사라지고 동작은 같습니다). 테이블은 서버가 처음 쓸 때 알아서 만듭니다. DB 가 느리거나 잠깐 죽어도 게임과 순위 조회는 계속되고(순위는 메모리에서 계산),
저장은 뒤에서 다시 시도합니다 (간격을 늘려 가며 약 18분 동안. 그 안에 DB 가 돌아오면 빠지는 기록이 없습니다).
서버가 켜질 때 DB 가 아직 안 되면(깨어나는 중 등) 저장된 기록을 불러올 때까지 순위표에 안내가 뜨고, 그동안 끝난 판은
기록은 되지만 결과 화면에서 순위를 알려주지 않습니다 (일부만 있는 목록으로 센 순위는 나중에 바뀌기 때문).
연결 문자열은 비밀번호가 들어 있으니 저장소에 커밋하지 마세요.
다른 PostgreSQL(Render 유료 Postgres, Supabase 등)도 같은 방법으로 쓸 수 있습니다.

### 다른 상시 실행 호스트 (Fly.io, Railway, VPS 등)

- 빌드: `npm ci --include=dev && npm run build` / 시작: `npm start` (Node 22 권장, 20+)
- 환경 변수: `SESSION_SECRET` (32자 이상 랜덤)
- 프록시 뒤라면 클라이언트 IP 출처를 지정: 엣지가 덮어쓰는 헤더가 있으면 `CLIENT_IP_HEADER`
  (예: Cloudflare 계열 `cf-connecting-ip`), 아니면 `TRUST_PROXY=<신뢰 프록시 홉 수>`. 자세한 내용은 `.env.example`
- 인스턴스는 반드시 1개로 둘 것 (방과 세션 기록이 프로세스 메모리에 있음)
- CPU 여유가 있는 서버라면 `WS_COMPRESS=1` 로 WebSocket 압축을 켜 전송량을 더 줄일 수 있습니다.
  0.1 CPU 급(Render 무료)에서는 켜지 마세요: 접속 수십 개로 서버 전체가 멈추는 것이 측정으로 확인됐습니다.

### 화면만 따로 배포하고 싶을 때 (선택)

클라이언트만 Vercel 등에 올릴 수도 있습니다 (`vercel.json`). 이때는 클라이언트 빌드 환경 변수에
`VITE_GAME_SERVER_URL=https://<게임 서버 주소>`, 서버 쪽에 `ALLOWED_ORIGINS=https://<클라이언트 도메인>` 을 넣습니다.

## 반응형 / 적응형

- **모바일 퍼스트 CSS**: 기본 = 세로 폰, 이후 `480 / 768 / 1024 / 1440px` 브레이크포인트로 확장 (`apps/client/src/style.css`)

## 보안 (요약)

클라이언트는 **아무것도 결정하지 않습니다.** 자세한 내용은 [docs/SECURITY.md](docs/SECURITY.md).

- 서버 권위 시뮬레이션: 위치·체력·경험치·드롭·점수 전부 서버 계산
- 클라이언트 메시지는 정해진 6종뿐이며(hello·input·pick·start·pause·ping) 전부 스키마/범위 검증, 위반 누적 시 차단
- 서버 발급 HMAC 세션 토큰(단기·1회용), Origin 검사, 연결/메시지 레이트리밋, 프레임 크기 제한
- 페어 방은 서버가 만든 무작위 코드(약 10억 가지)로만 들어올 수 있고, 틀린 코드도 세션 토큰을 하나 소모
- 일시정지는 혼자 하는 방에서만, 서버가 정한 시간 한도 안에서만 가능
- 시야 밖 정보는 전송하지 않음(맵핵 방지). 필드 아이템의 위치는 예외로, 찾아가라고 모두에게 알려주는 정보다
- 난수는 예측할 수 없게: 서버의 난수는 전부 운영체제 CSPRNG (레벨업 선택지·회복 아이템·필드 아이템과 적 스폰은 서로 다른 난수)
- 리더보드 기록은 판이 끝날 때 서버가 직접 쓴다 (클라이언트가 점수를 제출하는 통로가 없음)
- CSP 등 보안 헤더, DOM 은 `textContent` 만 사용(XSS 차단)
